# M1 results

Machine: Intel Core i7-13700H, 13.7 GB RAM, Windows 11. Python 3.14.5 in a repo-local `.venv`
(CI uses Python 3.12 on ubuntu-latest). Run on 2026-10-23/24.

M1 scope: plans with a falsifiable hypothesis, blast radius and abort conditions, checked by a
JSON Schema and eleven safety rules, sealed before the start, rendered as pre-flight briefs, and
judged against a metric series. **No fault is injected in M1** and no cluster is touched; the
metric series in `examples/series/` are synthetic, built by hand for the demo, not measured.

## Analyze

- First draft of the plan loader used `yaml.safe_load`, which turns `2026-11-05T14:00:00Z` into a
  `datetime`, so the schema's string check failed on valid plans. Root cause: YAML 1.1 implicit
  timestamp typing. Fix: a `SafeLoader` subclass without the timestamp resolver
  (`test_timestamps_stay_strings`).
- `safe_load` also expands aliases, so a small file can grow into a large document. The loader now
  refuses aliases (`test_yaml_aliases_rejected`).
- Network latency parameters were first written as durations (`200ms`), which the duration format
  (s, m, h) cannot express; they are integers in milliseconds (`latency_ms`, `jitter_ms`).

## Improve

The changes above are in the loader and the schema; the three shipped plans validate and seal.

## Control

- CI (`.github/workflows/ci.yml`): `make ci` (lint, mypy, tests, `gameday validate`, `brief --check`,
  `verify`), a step that fails if the unsafe plan is accepted, a step that checks the three demo
  verdicts, and pip-audit. Results are printed as `::notice` annotations.
- Mistake-proofing: the schema, the rules and the seal run on every push; a plan edited after
  sealing, or a brief edited by hand, fails CI.

## Verified only in CI / not measured yet

- The Python 3.12 run and the `::notice` annotations happen in GitHub Actions (not run here).
- Nothing needs Docker in M1.
- Not measured yet (M2): fault injection with Chaos Mesh, k6 load, real p99 and error rates under
