# Quality check 2026-11-01

The ten engineering rules, checked against the code at this commit. M1 is a local CLI over YAML,
JSON and lock files: it makes no network, database or subprocess calls.

| # | Rule | Status | Evidence |
|---|---|---|---|
| 1 | Every call can fail | pass | Only local file I/O. Every read is size-capped (`model.py:18`, `evaluate.py` `MAX_SERIES_BYTES`, `sealing.py` `MAX_LOCK_BYTES`); `OSError`/`ValueError` become exit 2 with `error: ...` (`cli.py` `main`). No `except: pass` or dropped exceptions (`grep -n except src`). |
| 2 | Writes safe to retry | fixed | The lock file and the briefs were written in place with `write_text`, so a crash could leave a truncated lock. Now `write_atomic` writes a temp file and renames it (`model.py:244-248`, used at `sealing.py:53`, `cli.py:86`). Sealing an unchanged plan returns the old seal (`sealing.py:62`); `test_seal_twice_is_idempotent` runs `gameday seal` twice and asserts one identical lock file and no temp file. |
| 3 | No race conditions | N/A | Single-threaded CLI with no shared in-process state. Two `gameday seal` runs on the same lock at once would race (last writer wins); sealing is a reviewed, serial step in a pull request, so this is documented here rather than locked. |
| 4 | Don't trust the clock | fixed | Current time is `datetime.now(UTC)` (`cli.py:97`). `parse_time` read a timestamp without a zone (e.g. `--now 2026-10-30T12:00:00`) as local time; it now refuses it (`model.py:44`). Plan timestamps are already forced to end in `Z` by the schema. No durations are measured. |
| 5 | Read before changing | pass | No environment variables are read (`grep -n environ src` is empty). Every path in README and Makefile exists (`audit_repo.py` OK). |
| 6 | Never break compatibility | pass | Plans carry `apiVersion: gameday/v1`, the lock file `version: 1`; the changes add no field and rename nothing. Naive timestamps were never valid in plans (schema pattern), so refusing them on `--now` and in the lock changes no valid input. |
| 7 | One source of truth | pass | The YAML plan is the source; `plans.lock.json` (digests) and `docs/gamedays/*.md` (briefs) are derived and checked in CI by `gameday verify` and `gameday brief --check`. Python: `requires-python >=3.11` (`pyproject.toml:11`), CI 3.12, README says 3.11+. |
| 8 | No secrets, validate input | fixed | Secret grep (`password|secret|token|api_key`) finds nothing. Series values `NaN`/`Infinity` (accepted by `json.loads`) passed validation and silently counted as breaches; now refused (`evaluate.py:46,63`). `--max-breaches -1` sliced the list from the end; now exit 2 (`cli.py:137`). |
| 9 | Tests that can fail | fixed | No `assert True`, skip or xfail. 4 of 21 hand mutants survived; 5 tests added to kill them, 8 more for the fixes (table below). |
| 10 | Re-verify | pass | `bash .tmp/check.sh`: ruff `All checks passed!`, mypy `Success: no issues found in 14 source files`, `128 passed`, plan checks pass, unsafe plan rejected, pip-audit `No known vulnerabilities found`, `chaos-gamedays: OK`. CI result in the commit history. |
